# 공장 부하 96구간 예측

ESS 운영 판단(하루 계획)은 최적화가 하고, 판단에 필요한 값 중 변동이 큰 공장 부하만 AI로 예측합니다.
이 폴더는 그 예측 모델을 학습하고, 가짜 백엔드와 AI 서버가 쓸 1년치 예측값을 만듭니다.

## 실제 백엔드와 연결

```
Spring 판단 엔진 ──(GET /load-forecasts?start=&slots=100)──> AI 서버 (ai/app/main.py, FastAPI)
                 <──(15분 칸마다 load_kw, peak_load_kw)──────
```

- AI 서버는 `ai/app/data/load_forecast_2018.json`(이 스크립트가 만든 예측값)에서 같은 달·같은 요일인 2018년 날짜의 값을 꺼내
  우리 공장 크기 kW(1,300 + 1.35 × kWh × 4)로 바꿔 돌려줍니다. 모델이 "매일 0시에 그날 96구간"을 예측하도록 학습되어 있어서,
  미리 계산해 둔 하루치 예측을 꺼내 쓰는 것과 같습니다.
- Spring(`LoadForecastService`)은 지난 1시간(4칸) 동안 예측이 빗나간 평균만큼 앞으로의 칸을 옮겨 씁니다.
  AI 서버가 응답하지 않으면 최근 1시간 평균 부하로 대신 계획합니다.
- 충전·방전 판단은 AI가 아니라 Spring 판단 엔진(최적화)이 합니다.

## 실행

저장소 루트에서 실행합니다.

```bash
pip install -r ai/forecast/requirements.txt
python ai/forecast/train_load_forecast.py
```

만드는 파일

| 파일 | 내용 |
|---|---|
| `ai/forecast/production_plan.csv` | 생산계획 더미 (날짜, 시각, 계획 부하 kW, 정상/휴무) |
| `frontend/src/api/fakeLoadForecast.json` | 1년치 96구간 예측값. `loadKwh` = 평균 예측(요금 계산용), `peakLoadKwh` = 상위 90% 예측(방어선 판단용) |

## 무엇을 예측하나

매일 0시에 오늘 00:00~23:45의 96구간 각각의 15분 평균 공장 부하(kW)를 예측합니다.

## 데이터

- 공장 부하: UCI Machine Learning Repository, Steel Industry Energy Consumption (CC BY 4.0). 2018년 1년치 15분 데이터(`frontend/src/api/fakeEnergyData.json`의 `loadKwh`).
- 생산계획(더미): UCI에는 생산계획이 없어서, 학습 기간(1~9월) 데이터로 요일·구간별 표준 일정(중앙값)을 만들어 계획 부하로 씁니다. 공휴일은 휴무로 보고 일요일 일정을 씁니다. 실제 생산계획이 생기면 이 부분만 그 CSV로 바꾸면 됩니다.

## 입력값 (특징)

| 특징 | 뜻 |
|---|---|
| `plan_kw` | 생산계획의 그 구간 계획 부하 |
| `slot` | 구간 번호 0~95 |
| `day_of_week`, `is_holiday`, `month` | 요일, 공휴일 여부, 월 |
| `lag_1d`, `lag_7d` | 어제·지난주 같은 구간 부하 |
| `mean_4w` | 최근 4주 같은 요일·같은 구간 평균 |
| `yesterday_max`, `yesterday_mean` | 어제 하루 최대·평균 부하 |

0시에 이미 알 수 있는 값만 씁니다. 휴일이었던 날의 기록은 평소 패턴이 아니라서 과거 기록 특징에서 뺍니다.

## 모델

scikit-learn `HistGradientBoostingRegressor` (그래디언트 부스팅)

- 표 형태 데이터에 강하고, 1년치(약 2만 5천 행) 데이터로 충분하며, 학습이 몇 초면 끝납니다.
- LightGBM과 같은 방식이고 이 데이터 크기에서는 성능이 거의 같아서, 평가 도구까지 함께 있는 scikit-learn을 씁니다.
- 모델 두 개를 만듭니다: 평균 예측(요금 계산용), 상위 90% 예측(방어선 판단용). 평균 예측은 하루 피크를 낮게 보는 경향이 있어서 피크 판단에는 보수적인 값을 씁니다.

## 검증 결과 (1~9월 학습 → 10~12월 예측, 우리 공장 크기로 환산한 kW)

| 지표 | 평균 예측 | 상위 90% 예측 |
|---|---|---|
| 96구간 평균 오차 | 56.5 kW (3.6%) | - |
| 하루 최대 피크 오차 평균 (예측 − 실제) | −130 kW | −4 kW |
| 하루 최대 피크 오차 절댓값 평균 | 183 kW | 152 kW |
| 하루 피크를 낮게 본 날 | 71% | 55% |

특징 중요도는 계획 부하(`plan_kw`)가 가장 크고, 그다음이 어제 평균 부하·어제 같은 구간 부하입니다.

## 시뮬레이터용 1년치 예측

가짜 백엔드는 1년 데이터를 해마다 반복해서 쓰므로, 1년치 예측이 모두 필요합니다. 각 달은 그 달을 뺀 나머지 11개월로 학습한 모델로 예측합니다. 예측하는 날의 실제 값은 학습에 들어가지 않지만 앞뒤 달의 데이터는 들어가므로 시연용이며, 성능 수치는 위의 검증 결과를 씁니다.

## 한계

- 실제 공장(UCI 제철소)과 우리 대상 공장은 설비와 규모가 다릅니다. "공개 실측 공장 데이터로 학습·검증한 모델"이고, 고객사에 적용할 때는 그 공장의 15분 데이터와 생산계획으로 다시 학습합니다.
- 생산계획이 더미라서, 특근·라인 정지 같은 날별 계획 변경 정보는 없습니다.
