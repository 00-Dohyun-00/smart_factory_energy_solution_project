## 4. 추이 분석
- 피드백 (이력·이벤트)
  - 5번(이력)과 6번을 합친다.
  - 6번 그래프에 핀이 찍히듯, 5번 이력도 그래프 위 시점에 표시한다. 이벤트 히스토리처럼 태깅하는 방식이다.
  - 이벤트가 많지 않다면 미리 핀을 꽂아 두는 게 좋다.
- **Q(멘토)** 시간대별 사용패턴이 선택한 기간에 따라 달라지나 → 현재는 아니다.
  - 피드백: 기간에 따라 x축 간격을 바꾼다. 하루를 고르면 1시간 단위, 한 달이면 하루 단위다.
  - 피드백: 시간대별 랭킹으로 보여주는 것도 좋다.

## 5. 피크 분석
- **Q(멘토)** 최대 피크는 한전과 태양광을 합친 값인가 → 아니다, 한전 전력만이다.
- **Q(멘토)** 목표를 넘은 구간이 15분 구간인가 → (답 기록 없음)
  - 피드백: 목표 초과 구간을 %로 보여주는 게 좋다.
- **Q(멘토)** 피크가 가장 많은 시간대를 히트맵으로 표시할 수 있나 → (답 기록 없음)
  - 피드백: 지난달 10시에 피크가 가장 많았다면 10시에 표시한다.
  - 피드백: 피크가 높았던 구간에서 특정 라인을 누르면 히트맵에 바로 표시되게 한다.
- 멘토도 평균 피크 저감과 총 피크 저감 중 무엇이 더 중요한지는 모르겠다고 했다.
- 단위
  - 고객은 원 단위를 선호하지만, 요금 수식이 계속 바뀐다.
  - 엔지니어는 와트 단위가 좋다.
  - 그래서 원 단위는 보고서에만 쓰면 될 것 같다.

## 6. 보고서·전기요금
- 피드백
  - 다른 페이지에 있는 같은 데이터를 보고서에 똑같이 넣어도 괜찮다.
  - 보고서 방식은 두 가지다. 일·주 단위 등 주기를 정해 이메일로 자동 발송하거나, 보고하는 사람이 기간을 정해 파일로 뽑는다.
  - 파일로 뽑을 때는 관리비 영수증처럼 화면보다 더 자세하게 나와야 한다.
  - 보고서는 위아래로 길어도 된다. 지금 레이아웃은 어렵게 잡혀 있으니 처음부터 세로로 길게 만든다.
  - 전기요금 추정에는 작년·지난달 납부액 비교를 넣는다. 통신비 청구서를 참고하면 좋다.
- **Q(멘토)** 사용 비용이 따로 저장되나 → 저장하지 않고 요금 기준표 테이블로 계산한다.
- **Q(멘토)** 3년 기록도 그 테이블로 확인할 수 있나 → 가능하다.
