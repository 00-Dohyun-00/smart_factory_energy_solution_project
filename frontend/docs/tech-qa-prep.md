# 개발 과정 · 기술 이해 질문 준비

발표 질의응답에서 "개발 과정"과 "기술을 얼마나 이해했는지"를 물어볼 때를 위한 준비 문서다. 2026-11-23 `dev` 코드 기준.

- 숫자 · 공식 · 데이터 질문은 [frontend-qa.md](frontend-qa.md)를 본다
- 이 문서는 "어떻게 만들었고, 왜 그렇게 했고, 코드를 설명할 수 있나"를 준비한다

> **핵심:** 이런 질문은 "직접 이해하고 만들었나"를 확인하려는 것이다. 특히 AI를 썼다고 하면 "AI가 짠 코드를 설명할 수 있나"를 꼭 묻는다. 많이 외우기보다 **내 코드로 설명할 수 있게** 준비한다.

## 1. 기능 하나를 처음부터 끝까지 설명하기 ⭐

가장 자주 나오는 질문: "이 숫자가 화면에 나오기까지 어떻게 흘러가요?"
하나만 완벽하게 준비한다. 추천은 **통합 화면의 예상 피크 카드**다.

```
MainLayout.vue          5초마다 realtimeStore.fetchLatest() 호출
   ↓
useRealtimeStore.js     getLatestBatteryStatus() 등 API 3개를 한 번에 요청
   ↓
batteryStatusApi.js     api('/site-powers/latest')
   ↓
client.js               fetch('/api/site-powers/latest')
   ↓
Vite 개발 서버           /api 요청을 백엔드 localhost:8080으로 넘김 (vite.config.js proxy)
   ↓
백엔드 SitePowerService  1분 기록으로 예상 피크 계산 → JSON 응답
   ↓
useRealtimeStore.js     status에 저장
   ↓
PeakWindowCard.vue      computed로 읽어서 숫자 · 그래프를 그림
```

- 화이트보드에 그리면서 **1분 안에** 말할 수 있으면 구조 질문은 대부분 통과
- "화면에서 fetch를 직접 안 부르는 이유"까지 붙이면 좋다 → 서버 주소와 오류 처리를 `client.js` 한 곳에 모으려고

## 2. 기본 개념을 내 말로 (한 줄씩)

| 폴링 | 정해진 주기마다 서버에 "새 값 있어요?" 묻기 | 5초 주기 |
| 프록시 | 개발 서버가 `/api` 요청을 백엔드로 대신 전달 | `vite.config.js` |

## 3. 결정마다 "왜 + 다른 방법은?"

면접관은 "왜 이렇게 했어요?" 다음에 "다른 방법은 생각 안 했어요?"를 묻는다.

| 결정 | 왜 | 다른 방법 | 왜 안 했나 |
|---|---|---|---|
| 폴링 5초 | 백엔드 기록이 1분 단위라 충분, 구현이 단순 | WebSocket, SSE | 서버가 밀어줄 만큼 자주 바뀌지 않음. 개선 과제로 남김 |
| UI 라이브러리 없음 | 웹이 처음인 팀이라 배울 것을 줄임 | Element Plus 등 | 라이브러리 사용법까지 익혀야 하고, 디자인을 맞추기 어려움 |
| JavaScript (TS 안 씀) | 같은 이유로 배울 것을 줄임 | TypeScript | 타입 문법을 따로 익혀야 함 |
| 계산은 백엔드 | 화면과 백엔드 숫자가 달라지는 것을 막음 | 프론트에서 계산 | 같은 계산을 두 곳에서 하면 결과가 어긋남 |
| 서버 시각 사용 | 시뮬레이터 시간과 PC 시계가 다를 수 있음 | 브라우저 시계 | 시뮬레이터가 멈춰도 시계가 흘러가 멈춘 걸 모름 |
| 값 없음은 `—` | 0과 "값 없음"을 구분 | 0으로 표시 | 통신이 끊긴 것을 "0 kW 사용"으로 오해함 |
| 끊겨도 값 유지 | 마지막 값과 받은 시각을 보여 주는 게 더 유용 | 값 지우기 | 화면이 비면 무슨 일인지 알 수 없음 |
| 차트는 `Chart.vue` 하나로 | 만들기 · 크기 조절 · 정리를 한 곳에서 | 화면마다 ECharts 직접 사용 | 정리를 빠뜨리면 메모리가 샘 |

## 4. 어려웠던 점: 이야기 4개

"문제 → 원인을 어떻게 찾았나 → 어떻게 고쳤나 → 어떻게 확인했나" 순서로 말한다.

### ① 바늘이 1분마다 툭 튐 (이슈 #32)
- **문제:** 계기판 바늘과 숫자가 1분마다 한 번에 뛰어서 어색함
- **원인:** 백엔드 기록이 1분 평균이라 1분에 한 번만 값이 바뀜
- **해결:** 값이 바뀌면 0.6초 동안 이전 값 → 새 값으로 옮겨 가게 함 (`KpiCards.vue`, `requestAnimationFrame`)
- **주의한 점:** 처음 받을 때 · 연결이 끊겼을 때 · 운영체제 "움직임 줄이기"가 켜져 있으면 움직이지 않음. 끝나면 받은 값 그대로

### ② 충전 중 "한전 104% · ESS -4%" (이슈 #35-1)
- **문제:** 공급원 비율이 100%를 넘고 음수가 보임
- **원인:** 백엔드가 충전을 음수로 줘서, 한전 = 100 − 태양광 − (음수)로 100을 넘음
- **해결:** 충전 중일 때만 화면에서 ESS 0%, 한전 = 100 − 태양광 (`KpiCards.vue`의 `displayRatio`)
- **남은 일:** 충전 중 비율 표현은 백엔드와 확정 필요 (#34-10)

### ③ 분이 바뀌는 순간 "0.0 kW" (이슈 #35-3)
- **문제:** 1~2초 동안 구역 합계가 0.0 kW로 깜빡임
- **원인:** 그 순간 백엔드가 설비 값을 비워(`null`) 보내는데, JavaScript에서 `0 + null = 0`이라 0으로 더해짐
- **해결:** 설비 하나라도 값이 비면 구역 합계를 `—`로 표시

### ④ 설정값 하나 때문에 요청이 쉬지 않고 나감 (이슈 #24, #25)
- **문제:** 화면 갱신 주기 설정에 이상한 값이 들어가면 폴링이 멈추지 않음
- **원인:** `setInterval(…, NaN)`은 쉬지 않고 실행됨
- **해결:** 숫자가 아니거나 1보다 작으면 기본 5초를 씀 (`MainLayout.vue`의 `pollSeconds`)

## 5. 개발 과정 질문

### Q. 팀은 어떻게 협업했나요?
- **브랜치:** `feat/…`, `fix/…` 기능 브랜치에서 작업 → `dev`에 병합 → `main`은 PR로만 (직접 push 금지)
- **커밋 규칙:** `타입: 설명` (예: `fix: 충전 중 공급원 비율이 음수로 보이는 문제 수정`)
- **소통:** 문제를 찾으면 GitHub 이슈에 "무엇이, 어느 파일 몇째 줄에서, 왜"를 적어 담당자에게 넘김
- **역할:** 프론트는 화면, 백엔드는 API · 계산. 남의 영역 코드는 고치지 않고 이슈로

### Q. 잘 만들어졌는지 어떻게 확인했나요?
- `npm run format && npm run lint && npm run build` 통과해야 끝
- 화면은 직접 열어 1920×1080, 1366×768에서 확인 (헤드리스 Chrome 포함)
- 정상 · 피크 초과 · 값 없음 · 서버 끊김 · 빈 목록 상태를 모두 확인
- 공용 DB는 읽기만 하고, 설정 저장 같은 쓰기는 팀에 알리고 함

### Q. AI는 어떻게 썼나요? ⭐
정직하게 말하는 게 가장 안전하다.

> "AI로 초안을 만들고 점검을 했습니다. 저는 규칙 파일(AGENTS.md, CLAUDE.md)로 AI가 지킬 약속을 정하고, 나온 코드를 직접 읽고 자동 검사와 화면 확인으로 검증했습니다. 연결 점검에서는 찾는 AI와 확인하는 AI를 나눠서 31건 중 30건을 걸렀습니다."

- 이 답을 하려면 **아래 6장의 파일은 아무 줄이나 짚어도 설명할 수 있어야** 한다

## 6. 줄 단위로 설명할 수 있어야 할 코드

### `layouts/MainLayout.vue` — 폴링
| 물어볼 만한 것 | 답 |
|---|---|
| `pollSeconds`는 왜 `computed`? | 설정에서 주기를 바꾸면 자동으로 새 값이 되게 하려고. `watch(pollSeconds, startPolling)`으로 바뀌면 다시 시작 |
| 왜 `onBeforeUnmount`에서 `clearInterval`? | 안 하면 화면을 떠나도 계속 요청하고, 다시 들어오면 폴링이 겹쳐 두 배로 요청함 |
| `visibilitychange`는 왜? | 탭이 안 보이면 폴링을 멈춰 공용 DB 사용량을 줄이고, 다시 보이면 바로 한 번 받음 |
| 왜 여기서 폴링? | 왼쪽 메뉴(시계 · 날씨 · 연결 표시)가 모든 화면에 있어서 한 곳에서만 받음 |

### `stores/useRealtimeStore.js` — `fetchLatest`
| 물어볼 만한 것 | 답 |
|---|---|
| `Promise.all`은 왜? | 최신 상태 · 추천 · 이벤트 3개를 동시에 요청해 기다리는 시간을 줄임 |
| 3개 중 하나만 실패하면? | `Promise.all`은 하나라도 실패하면 전체가 실패 → `catch`로 가서 실패 횟수만 올리고 값은 유지 |
| `requesting`은 뭐? | 앞 요청이 안 끝났으면 다음 폴링을 건너뜀 (요청이 쌓이지 않게) |
| `requestId`는 뭐? | 늦게 온 옛 응답이 새 값을 덮어쓰지 않게 번호를 확인 |
| 연결 끊김 기준은? | 3번 연속 실패 (한 번 실패로 깜빡이지 않게) |
| 기록 멈춤은 어떻게 알아? | 서버의 지금 시각(구간 끝 − 남은 초)과 마지막 기록 시각 차이가 3분 이상이면. 브라우저 시계는 안 씀 |

### `api/client.js` — 공통 요청 함수
| 물어볼 만한 것 | 답 |
|---|---|
| 주소 앞에 `/api`를 붙이는 이유? | 개발 서버가 `/api`로 시작하는 요청만 백엔드로 넘기기 때문 (`vite.config.js` proxy) |
| CORS 문제는 없었나? | 프록시 덕분에 브라우저 입장에선 같은 주소로 요청해서 생기지 않음 |
| 오류 처리는? | 백엔드가 보낸 메시지가 있으면 그대로, 서버에 닿지 못하면 "서버에 연결할 수 없습니다." |
| 204는? | 본문이 없는 성공(예: 추천 없음)이라 `null`을 돌려줌 |

### `components/KpiCards.vue` — 바늘 움직임 · 비율
| 물어볼 만한 것 | 답 |
|---|---|
| 움직임은 어떻게? | `requestAnimationFrame`으로 0.6초 동안 화면을 그릴 때마다 사이 값을 계산 (처음 빠르고 끝에서 천천히) |
| 왜 CSS 애니메이션이 아니라 JS? | 숫자 글자와 SVG 바늘, 비율 색을 같은 사이 값으로 함께 움직이려고 |
| `displayRatio`는? | 충전 중(ESS가 음수)일 때만 ESS 0%, 한전 = 100 − 태양광으로 바꿈. 나머지는 받은 값 그대로 |

### `components/PeakWindowCard.vue` — 15분 그래프
| 물어볼 만한 것 | 답 |
|---|---|
| `points`에서 0분 점을 붙이는 이유? | 백엔드는 1분 점부터 줘서, 구간이 막 바뀌어 점이 1개면 선이 안 보였음 |
| 이 카드에서 계산하는 게 있나? | 그래프 세로축 끝과 남은 시간 막대 비율 정도(표시용). 예상 피크 · 단계는 백엔드 값 |

## 7. 꼬리 질문 모음

| 질문 | 짧은 답 |
|---|---|
| `computed`와 함수(method)의 차이는? | `computed`는 결과를 기억해 두고 의존 값이 바뀔 때만 다시 계산. 함수는 부를 때마다 계산 |
| 스토어를 구조 분해하지 않는 이유는? | `const { status } = store`처럼 꺼내면 값이 바뀌어도 화면이 안 따라옴 (반응성이 끊김) |
| `v-if`와 `v-show` 차이는? | `v-if`는 아예 안 만들고, `v-show`는 만들고 숨김. 차트는 크기 0에서 오류가 나서 숨기는 탭은 `v-if` |
| 차트 애니메이션을 끈 이유는? | 값이 계속 바뀌는 화면이라 매번 움직이면 깜빡임 |
| 0과 `null`을 왜 구분하나요? | `0 + null = 0`이라 값이 빈 것을 0 kW로 오해함 → `—`로 표시 |
| 브라우저 시간을 안 쓰는 이유는? | 시뮬레이터 시간과 다를 수 있고, 시뮬레이터가 멈춘 것을 알아채기 위해 |
| 테스트 코드는 있나요? | 자동 테스트는 없음. 포맷 · 린트 · 빌드 검사와 화면 상태별 직접 확인으로 검증. 개선 과제 |
| 보안은요? | 비밀번호 · 접속 정보는 `.env`에만 두고 커밋하지 않음. 로그인은 이번 범위에서 뺌 |
| 성능 문제는 없었나요? | 탭이 안 보이면 폴링 정지, 앞 요청 중이면 건너뜀, 백엔드는 1초 응답 캐시. 빌드 파일 약 1.37 MB(대부분 ECharts) |
| 다시 만든다면? | 폴링 → SSE, 자동 테스트, 설비 임계치를 DB 설정으로, 실제 하루 흐름 데이터 |

- [ ] 2장 개념을 한 줄씩 내 말로 말할 수 있다
- [ ] 3장 결정 중 3개 이상을 "왜 + 다른 방법"으로 말할 수 있다
- [ ] 4장 이야기 중 2개를 순서대로 말할 수 있다
- [ ] 6장 파일 5개를 열고 아무 줄이나 짚어도 설명할 수 있다
- [ ] AI 사용 질문에 30초 답을 준비했다
- [ ] 모르는 질문 대응 문장을 입에 붙였다
