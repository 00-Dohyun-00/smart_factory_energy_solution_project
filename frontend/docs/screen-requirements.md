- **범위:** 사용자가 화면에서 보고 조작하는 기능. 백엔드 내부 계산(예상 피크, 추천 판단, 요금)의 자세한 식은 [frontend-qa.md](frontend-qa.md), API 모양은 [api-spec.md](api-spec.md)

## 0. 읽는 법

### 공통 원칙

- 피크 예측 · 단계 · 추천 · 요금 · 탄소는 **백엔드가 계산**하고 화면은 표시만 함. 프론트 계산은 합계 · 비율 · 단위 변환 · 축 범위 같은 **표시용**만
- "지금" 시각은 서버 값(`recordedAt`, `windowEnd − remainingSeconds`)으로 구함. 브라우저 시계는 쓰지 않음
- 값이 없으면 `—` (0과 구분). 금액 · 탄소는 "추정"으로 표시
- 상태는 색만 쓰지 않고 **도형 + 글자 + 색**: `● 정상` `▲ 주의` `■ 경고` `◆ 통신 단절` `○ 불러오는 중`
- 공용 DB라 [적용] · [넘기기] · 설정 저장은 팀원 모두에게 바로 반영됨

### 번호 규칙

- 화면 `SCR-nn`, 기능 `SCR-nn-mm`
- **계산** 칸: `백엔드` = 받은 값 그대로 / `프론트` = 표시용 계산(식을 적음)

**규칙 · 상태**

- 갱신 주기 = 설정 `operation.poll_seconds`(숫자가 아니거나 1 미만이면 5초). 값이 바뀌면 폴링을 다시 시작
- 탭이 숨겨지면 폴링을 멈추고, 다시 보이면 바로 1번 받음. 앞 요청이 안 끝났으면 다음 차례는 건너뜀
- 3개 API 중 하나라도 실패하면 그 회차 전체를 실패로 셈. 실패해도 마지막 값은 유지
- 설정(`GET /api/settings`)은 앱을 열 때 한 번만 받음
- 연결 끊김 띠 문구: "◆ 서버와 연결되지 않습니다. 화면의 값은 HH:MM:SS에 마지막으로 받은 값입니다. … 5초마다 자동으로 다시 연결합니다." / 값을 못 받았으면 "아직 값을 한 번도 받지 못했습니다."
- 개발 서버에서 주소에 `?fake`를 붙이면 가짜 백엔드로 동작 (빌드에는 없음, [fake-backend-mode.md](fake-backend-mode.md))

**상세 규칙**

- **KPI 부드러운 전환:** 값이 바뀌면 0.6초 동안 이전 값 → 새 값으로 옮겨 감 (첫 값, 끊김, "움직임 줄이기" 설정이면 바로 바꿈)
- **구매전력이 목표를 넘으면:** 아랫줄을 "▲ 순간값이 목표 초과 (피크 판정은 15분 평균)"로 바꿈. 큰 숫자는 경고색으로 바꾸지 않음
- **충전 중 공급원 비율 (커밋 전, #35-1):** 백엔드가 충전을 `essPercent < 0`으로 주면 화면은 ESS 0%, 한전 = max(0, 100 − 태양광)
- **예상 피크 단계:** 백엔드 `peakStatus` 그대로(● 정상 / ▲ 주의 / ■ 경고, 경고면 카드 테두리 빨강). 끊기면 ◆ 통신 단절, 첫 값 전에는 ○ 불러오는 중
- **15분 흐름 그래프:** 실선 = 현재 누적(`windowPoints`), 점선 = 지금 → 15분의 예상 피크, 자주색 목표선, 아직 오지 않은 시간은 옅은 띠
- **추천 카드 모양 5가지:** 추천 없음 / 대기(IDLE) / 답 기다림(버튼 있음) / 적용 중(APPLIED · AUTO) / 넘김(IGNORED, 넘김과 만료 둘 다)
- **버튼 비활성:** 요청 중("보내는 중…") 또는 연결 끊김("◆ 서버와 연결이 끊겨 지금은 적용할 수 없습니다"). 최신 추천 1건에만 버튼이 있음
- **적용 실패:** 카드 아래 빨간 글자로 백엔드 문구(예: "이미 지난 추천입니다. 최신 추천을 확인해 주세요.")
- **운영 모드 확인 창:** "운영 모드를 바꿀까요?" + "▲ 공용 설정이라 저장하면 모든 팀원의 화면에 바로 적용됩니다." 실패하면 "운영 모드를 바꾸지 못했습니다. (메시지)"
- **금일 그래프 갱신:** 화면을 열 때 + 15분 구간이 바뀔 때(`windowStart` 변경). 최대부하 회색 띠, 목표선, "지금 HH:MM" 세로선 포함
- **이벤트 종류:** 단계 변화 / 추천 / 적용 · 넘김 / 구간 종료 / 통신 / 설정 변경 (백엔드 `eventType`)

**상태 처리**

- 첫 로딩: 화면 전체 스피너 "실시간 데이터를 불러오는 중입니다."
- 연결 끊김: KPI 숫자 · 바늘 회색 + "◆ 연결이 끊겨 HH:MM:SS 값에서 멈춰 있습니다", 값은 유지
- 그래프: 실패 "그래프를 불러오지 못했습니다. (메시지)" + [다시 시도] / 빈 값 "오늘 기록이 아직 없습니다." (그래프가 이미 있으면 다시 받기 실패해도 그대로 둠)
- 이벤트: "아직 기록된 이벤트가 없습니다." / 필터 결과 없음 "조건에 맞는 이벤트가 없습니다."
- 예상 피크 값 없음: "값을 기다리는 중입니다."

**상세 규칙**

- **절대값 게이지:** 끝 값 = 임계치 ÷ 0.9 (임계치가 막대 90% 지점). 90~100% 구간 빨간 반투명 + 90% 눈금. 막대 아래 "0 / 끝 값 kW"
- **구역 임계 합:** 그 구역 설비 임계치의 합 (한 대라도 없으면 계산 안 함)
- **설비 임계치 출처 (커밋 전, #35-2):** 설정 `equipment.{설비 id}.max_kw`. DB에 행이 없어 **프론트 기본값 = 설비 정격 전력**(`useSettingsStore.js`, 15대)을 씀. 기본값에 없는 설비는 "임계 미설정"이고 초과 판정 안 함
- **구역 상세 갱신:** 화면을 열 때, 구역을 바꿀 때, `recordedAt`의 "분"이 바뀔 때. 받은 상세의 구역이 고른 구역과 같을 때만 보여 줌
- **원그래프 클릭:** 공통 `Chart.vue`가 클릭을 알려 주지 않아 누른 위치의 각도로 조각을 찾음 (도넛 고리 밖은 무시)
- 차단기 네모는 그림 기호이고, 화면 전체가 보기 전용(제어 기능 없음)

**상태 처리**

- 첫 로딩: 화면 전체 스피너 "실시간 데이터를 불러오는 중입니다."
- 최근 1시간: 받는 중 스피너 / 실패하고 보여 줄 값이 없으면 "불러오지 못했습니다." + [다시 시도]
- 값 없음: 설비 kW가 비면 그 설비와 그 구역 합계 · 비율이 `—`, 원그래프는 회색 고리(이슈 #35-3: 분이 바뀌는 순간 백엔드가 설비 값을 비워 보냄)
- 연결 끊김: 계통도 숫자 회색, 원그래프 두 개 "연결 끊김" 회색 고리(툴팁 · 클릭 꺼짐), 오른쪽 상세는 마지막 값 유지

- **주소:** `/analysis/trend` (예전 피크 분석 화면을 합침)
- **목적:** 고른 기간의 공장 소비 · 한전 구매 · 태양광 · ESS 방전 1시간 추이와 15분 피크 실적(일별 최대 피크, 목표 초과, 높았던 구간)을 한 화면에서 봄

  3. 왼쪽: 전력 그래프(2) / 일별 최대 피크(1) | 오른쪽(480px, 1,600px 이하 400px): 시간대별 사용 패턴 / 피크가 높았던 구간

**상세 규칙**

- **기간 한도:** 121일 (추이 · 피크 API 모두). 시작일 > 종료일이거나 121일을 넘으면 요청하지 않음
- **자동 갱신:** 종료일이 오늘 이후면 15분 구간이 바뀔 때마다 "불러오는 중" 없이 다시 받음 (시간대별 패턴 막대는 보던 위치를 지키려고 그대로 둠)
- **요청 순서:** 기간을 빨리 바꿔도 가장 최근 요청의 응답만 반영. 피크 결과는 기간이 같을 때만 씀
- **추천 처리 표시:** 없음 → "방전 추천 없음" / `APPLIED` ● 방전 적용 / `AUTO` ◇ 자동 방전 (시뮬레이션) / `IGNORED` ✕ 추천을 넘김 / 그 밖 ○ 추천 중
- **세로축:** 전력 그래프는 목표가 데이터보다 크면 위 끝을 목표 × 1.05(500 단위)로 올림. 일별 막대는 최소값 × 0.9(100 단위)부터
- **링크:** ● 점 → `/logs/power?at={15분 구간 시작}`, "추천 이력 보기" → `/logs`

**상태 처리 (화면 문구)**

- 날짜 오류: "시작일이 종료일보다 늦습니다." / "기간은 최대 121일까지 조회할 수 있습니다."
- 서버 시각 전: "서버에서 현재 시각을 받으면 자동으로 조회합니다." / 첫 조회: "불러오는 중입니다."
- 실패(결과 없음): "분석 결과를 불러오지 못했습니다. (메시지)" + [다시 시도]
- 실패(이전 결과 있음): "◆ 새 결과를 불러오지 못해 이전에 받은 결과를 보여 줍니다. (메시지)" + [다시 시도]
- 기록 없음: "이 기간에는 기록이 없습니다. 기간을 바꿔 보세요."
- 피크 영역: "피크 기록을 불러오지 못했습니다. (메시지)" + [다시 시도] / "이 기간에는 피크 기록이 없습니다." / "이 기간에는 구간 기록이 없습니다."
- 보기 0개: "\"보기\"에서 볼 항목을 하나 이상 골라 주세요."

- 운영 모드 · 갱신 주기는 저장 즉시 공통 틀(폴링 주기, 자동 모드 표시)에 영향
- 변경 기록 기간은 서버 날짜(`recordedAt`) 기준 30일 고정

**상태 처리**

- 로딩: 스피너 / 실패: "기준값을 불러오지 못했습니다. (메시지)" + [다시 시도]
- 변경 기록: 실패 "변경 기록을 불러오지 못했습니다. (메시지)" + [다시 시도] / 없음 "최근 30일 동안의 변경 기록이 없습니다."

## 10. 확인 필요 (코드를 읽다 찾은 것)

코드를 읽어 찾은 것이고, 화면에서 재현해 보지는 않았다.

### 오류가 날 수 있는 곳

| 화면           | 내용                                                                                                                                                  | 위치                                             |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 통합           | `status.tariff`가 null이면(요금표에 빈 시각, API 명세상 가능) 제목 줄 · 그래프에서 화면 오류                                                           | `MonitoringPage.vue:393, 157`                    |
| 통합           | `targetPeakKw`가 null이면 구매전력 % 가 Infinity → "▲ 순간값이 목표 초과" + 빨강으로 잘못 표시                                                         | `KpiCards.vue:149-151`                           |
| 설비 모니터링  | 오른쪽 구역 비율이 `loadKw`가 0/null인지 확인하지 않음 → "공장의 ∞%" 가능 (계통도는 확인함)                                                          | `PowerDiagramPage.vue:128-130`                   |
| 공통           | [지금 다시 시도]가 `force` 없이 불러서, 폴링 요청이 진행 중이면 아무 일도 안 함                                                                       | `MainLayout.vue:118`                             |
| 공통           | 연결 끊김 문구 "5초마다"가 글자로 고정 (실제 주기는 `operation.poll_seconds`)                                                                         | `MainLayout.vue:344`                             |

### 규칙 · 설명과 다른 곳

- **통합:** 운영 모드 버튼이 연결이 끊겨도 눌림 (저장 실패 문구만 나옴)
- **공통:** 설정을 앱을 열 때 한 번만 받아서, 팀원이 자동 모드를 바꾸면 새로 고치기 전까지 내 화면 표시가 안 바뀔 수 있음
- **통합 KPI:** 공급원 비율이 정수 % (규칙은 "% 소수 1자리")
- **설비 모니터링:** 오늘 사용량이 정수 kWh (규칙은 "kWh 소수 1자리"). 구역 원그래프 툴팁 %(설비 합 대비)와 왼쪽 "공장의 N%"(`loadKw` 대비)가 다를 수 있음
- **추이 분석:** 일별 막대 색 판정은 추이 API 목표를, 목표선은 피크 API 목표를 씀. "피크 기록은 121일까지만…" 안내는 추이 한도도 121일이라 실제로 안 뜸
- **월간 성적표:** ESS "잔량 부족" 이름과 백엔드 `blockedCount` 설명("적용했는데도 목표를 넘은 횟수")이 다름. 제목 줄 · 맨 아래 "추정값" 안내 문구는 주석 처리돼 안 보임
- **추천 이력:** 화면 한도 62일, 백엔드 121일. 탭이 다시 보여도 곧바로 받지 않고 다음 5초를 기다림
- **전력 이력:** 값이 없는 칸이 `—`가 아니라 빈칸 (CSV와 맞추려는 선택으로 보임)
- **환경 설정:** 변경 기록 기간이 서버 날짜(마지막 1분 기록) 기준이라, 시뮬레이터가 멈춘 뒤 바꾼 기록은 기간 밖이 될 수 있음. `poll_seconds` · `decision_valid_minutes`는 주석상 "화면에서 뺄지 팀 결정 대기"
- **커밋 전 임시 규칙:** 충전 중 공급원 비율 보정(#35-1), 설비 임계치 프론트 기본값(#35-2) — 백엔드와 표현 · 값이 정해지면 바꿀 곳
