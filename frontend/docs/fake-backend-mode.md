# 가짜 백엔드 모드 사용법

백엔드 서버 없이 **프론트엔드만 켜서** 화면을 움직여 보는 방법입니다.
시연 영상을 찍을 때, 백엔드가 꺼져 있을 때, "서버 연결 끊김" 같은 실패 화면을 확인할 때 씁니다.

- 값은 `frontend/src/api/fakeBackend.js`가 만든 **가짜 값**입니다. 공용 DB에는 아무것도 읽거나 쓰지 않습니다.
- **개발 서버(`npm run dev`)에서만** 켜집니다. `npm run build`로 만든 결과물(배포용)에는 들어가지 않습니다.

---

## 1. 켜는 법

1. 개발 서버를 켭니다. 백엔드(Docker)는 꺼져 있어도 됩니다.

   ```bash
   cd frontend
   npm install    # 처음 한 번만
   npm run dev
   ```

2. 브라우저에서 주소 끝에 **`?fake`** 를 붙여 엽니다.

   ```
   http://localhost:5173/?fake
   ```

3. 켜졌는지 확인합니다.
   - 왼쪽 메뉴 아래에 **"시뮬레이션 10배속"** 이 보입니다. (실제 백엔드는 배속이 없어서 이 글자가 안 보입니다.)
   - 개발자 도구(F12) → Console에 `[fake] 가짜 백엔드로 동작 중` 이 찍힙니다.

> 다른 화면에서 바로 시작하려면 그 화면 주소 뒤에 붙이면 됩니다. 예: `http://localhost:5173/monitoring/diagram?fake`

`?fake`를 빼고 열면 원래대로 실제 백엔드(`localhost:8080`)를 씁니다.

---

## 2. 주소 옵션

여러 개를 같이 쓸 때는 `&`로 잇습니다. (예: `?fake&scenario=spike&speed=5`)

| 주소                           | 하는 일                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------- |
| `?fake`                        | 가짜 값으로 동작 (기본 10배속)                                                  |
| `?fake&speed=5`                | 배속 바꾸기. 1(실제 속도) ~ 120. 10배속이면 15분 구간이 1분 30초, 5배속이면 3분 |
| `?fake&scenario=spike&speed=5` | **촬영용 "튐" 시나리오** (3절)                                                  |
| `?fake&scenario=peak`          | 오늘을 "1년 중 피크가 가장 높았던 날"로 바꿈. 처음부터 경고와 방전 추천이 보임  |
| `?fake=offline`                | 화면을 연 지 10초 뒤부터 서버 연결 끊김 흉내 (빨간 안내 띠, "◆ 연결 안 됨")     |
| `?fake=chart-error`            | 금일 전력 추이 그래프만 불러오기 실패 흉내                                      |

> `fakeBackend.js` 주석에 `?scenario=peak`, `?speed=30`처럼 `?fake` 없이 적힌 예시가 남아 있습니다. 지금은 앞에 `?fake`를 꼭 붙여야 가짜 백엔드가 켜집니다.

---

## 3. 촬영용 "튐" 시나리오 (`scenario=spike`)

ESS가 피크를 막는 장면을 영상으로 찍기 위해 만든 시나리오입니다.

```
http://localhost:5173/?fake&scenario=spike&speed=5
```

### 흐름

| 순서             | 화면에 보이는 것                                                                      |
| ---------------- | ------------------------------------------------------------------------------------- |
| 1. 정상          | 공장 소비전력 약 1,250 kW, 예상 피크 "● 정상", ESS 추천 "대기" (목표 피크 1,500 kW)   |
| 2. 피크가 튐     | 여러 설비가 한꺼번에 돌아 약 700 kW가 늘어남 → 예상 피크 "▲ 주의" → "■ 경고"          |
| 3. 방전 추천     | 튄 지 조금 뒤 "방전" 추천이 뜸 → **[적용]** 을 누르면 예상 피크가 "● 정상"으로 내려옴 |
| 4. 설비 모니터링 | 사출 · 유틸리티 구역이 가장 많이 늘어남. 설비마다 임계치 안이라 "▲ 초과"는 뜨지 않음  |
| 5. 다시 정상     | 튐이 끝나면 ESS 방전이 0이 되고 추천이 "대기"로 바뀜 → 구간이 끝나면 "구간 종료" 기록 |

### 시간 (5배속 기준)

- 페이지를 열고 **약 1~4분 뒤** 튀기 시작합니다. (화면 시각으로 3분 뒤에 처음 시작하는 15분 구간의 1분째)
- 튀는 시간은 **약 1분 50초**입니다. (화면 시각으로 9분)
- **6분마다** 되풀이됩니다. (화면 시각으로 30분)
- 촬영 전에 한 번 돌려 보고 언제 튀는지 감을 잡아 두면 편합니다. 지금 15분 구간은 "예상 피크" 카드 오른쪽 위(예: `17:15 – 17:30`)에 보입니다.

---

## 4. 주의할 점

- **새로 고침하면 처음부터 다시 시작합니다.** 적용한 추천, 바꾼 설정, 시나리오 진행이 모두 처음 상태로 돌아갑니다. (설정 저장도 브라우저 안에만 저장되고 공용 DB는 바뀌지 않습니다.)
- **메뉴로 화면을 옮기면 주소에서 `?fake`가 사라집니다.** 그래도 가짜 모드는 계속 켜져 있습니다. 하지만 이 상태에서 새로 고침(F5)하면 실제 백엔드로 돌아갑니다. 그럴 때는 `?fake`가 붙은 주소로 다시 여세요.
- **촬영 중에는 코드 파일을 고치지 마세요.** 파일을 저장하면 개발 서버가 화면을 자동으로 새로 고쳐서, 위와 같이 실제 백엔드로 돌아가거나 시나리오가 처음부터 다시 시작합니다.
- **가짜 백엔드에 없는 기능**이 있어 그 부분은 비어 보입니다.
  - 전력 이력 화면(설비별 전력, 기간별 이벤트)
- 화면의 시각은 배속만큼 빨리 흐르는 **가짜 시각**입니다. 실제 시각과 다릅니다.

---

## 5. 어떻게 동작하나

```
main.js ──(?fake가 있으면)──> api/fakeFetch.js ──> api/fakeBackend.js
            브라우저의 fetch를 가로챔        /api/... 요청에 가짜 값으로 답함
```

- `main.js`: 개발 서버이고 주소에 `?fake`가 있을 때만 `fakeFetch.js`를 불러온 뒤 화면을 띄웁니다.
- `fakeFetch.js`: 브라우저의 `fetch`를 가로채서 `/api/...`로 가는 요청을 `fakeBackend.js` 함수로 연결합니다. 화면 코드와 `client.js`는 그대로입니다.
- `fakeBackend.js`: 공장 전력, 태양광, ESS, 추천, 이벤트, 설정 값을 만듭니다.

**새 API를 추가했는데 가짜 모드에서 안 나오면** `fakeFetch.js`의 `ROUTES` 목록에 그 주소가 없는 것입니다. 목록에 없는 주소는 "가짜 백엔드에 없는 주소입니다."(404)로 답합니다.
